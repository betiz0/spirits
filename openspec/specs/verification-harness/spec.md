# verification-harness Specification

## Purpose

リポジトリで tmux を使って行う対話検証(コンパイル済みバイナリの起動確認、TUI 表示の確認、ネットワーク送信の確認など)について、検証の成否・中断・タイムアウトにかかわらず、検証が起動したプロセスと一時リソースを回収する。あわせて、回収漏れを検査できる手順として維持する。

## Requirements

### Requirement: 実行環境の確認
検証ランナーは、tmux が無い環境では `run` を開始せず、tmux が必要である旨を表示して非ゼロで終了しなければならない。(SHALL)
systemd user session が無い環境でも、`run` と `check` は動作しなければならない。(SHALL)

#### Scenario: tmux が無い環境
- **WHEN** tmux が PATH に無い環境で `scripts/tmux-verify.sh run` を実行する
- **THEN** ペインと実行記録は作られず、tmux が必要である旨が表示され、終了コードは非ゼロになる

### Requirement: 一意なセッション名
`run` は、`--session` で指定した名前にハッシュ値を付けてセッション名を生成し、ペインを起動する前に、そのセッション名を標準出力の1行目に出力しなければならない。(SHALL)
`run` は、既存の tmux セッションと実行記録を上書きしてはならない。生成したセッション名が既存のものと一致した場合は、開始せずに非ゼロで終了しなければならない。(SHALL)

#### Scenario: 同じ名前での繰り返し実行
- **WHEN** 同じ `--session` 名で `run` を2回実行する
- **THEN** 2回の実行はそれぞれ異なるセッション名を出力し、実行記録も別々に残る

### Requirement: 検証実行の記録
検証ランナーは、検証コマンドの実行を開始する前に、次の項目を実行記録として永続化しなければならない。(SHALL)
- セッション名
- ペインの PID と開始時刻
- セッション ID
- cgroup
- 一時パス
- 宣言したポート
- 1段階目のタイムアウト値
- 実行したコマンド

実行記録は、検証ランナー自身が SIGKILL で終了した場合も残らなければならない。(SHALL)

#### Scenario: 実行記録の作成
- **WHEN** `scripts/tmux-verify.sh run` で検証コマンドを起動する
- **THEN** 検証コマンドが実行を開始した時点で、上記の項目をすべて含む実行記録が存在する

#### Scenario: ランナーの強制終了
- **WHEN** `run` の実行中に、ランナーを SIGKILL で終了させる
- **THEN** 実行記録は残り、続けて実行した `check` はペインのプロセスの PID を出力して非ゼロで終了する

### Requirement: 検証の終了
`run` は、ペインの終了、セッションの消滅、タイムアウトのいずれかが起きるまで待ち、起きた時点で回収を行わなければならない。(SHALL)

#### Scenario: セッションの終了による回収
- **WHEN** `run` の実行中に `tmux kill-session` でセッションを終了する
- **THEN** `run` は1段階目のタイムアウトを待たずに回収を行い、残存がなければ終了コード 0 で終わる

### Requirement: 1段階目のタイムアウト
1段階目のタイムアウトは、検証コマンドの開始から数え、既定で 180 秒としなければならない。(SHALL)
この値は、ユーザ設定ファイル `${XDG_CONFIG_HOME:-$HOME/.config}/spirits-verify/config` の `TIMEOUT_SECONDS` で変更できなければならない。(SHALL)
設定値が正の整数でない場合、`run` はペインを起動せずに非ゼロで終了しなければならない。(SHALL)

1段階目を超えた場合、`run` は回収せず、次の項目を出力してから、1段階目と同じ長さだけ延長を待たなければならない。(SHALL)
- 経過時間
- CPU 数
- ロードアベレージ
- 空きメモリ
- 延長の受付期限

延長の待機中に延長がない場合、`run` は回収を行い、タイムアウトで回収したことを出力して、非ゼロで終了しなければならない。(SHALL)

#### Scenario: 1段階目の超過
- **GIVEN** 設定ファイルで `TIMEOUT_SECONDS=2` を指定している
- **WHEN** 延長もセッションの終了もしないまま検証を続ける
- **THEN** 開始から 2 秒後に、経過時間・CPU 数・ロードアベレージ・空きメモリ・受付期限が出力され、その時点ではペインのプロセスは残っている
- **AND** さらに 2 秒後に回収され、`run` は非ゼロで終了する

#### Scenario: 不正な設定値
- **WHEN** 設定ファイルの `TIMEOUT_SECONDS` が `0` または数値でない値である
- **THEN** ペインは起動されず、`run` は非ゼロで終了する

### Requirement: 延長と2段階目のタイムアウト
`extend` による延長は、延長の待機中に1回だけ受け付けなければならない。受け付けた時点から指定秒数を、2段階目のタイムアウトとしなければならない。(SHALL)
延長の待機中でない場合、`extend` は延長せずに非ゼロで終了しなければならない。(SHALL)
2段階目のタイムアウトを超えた場合、`run` は回収を行い、タイムアウトで回収したことを出力して、非ゼロで終了しなければならない。(SHALL)

#### Scenario: 延長後の2段階目の超過
- **GIVEN** 設定ファイルで `TIMEOUT_SECONDS=2` を指定している
- **WHEN** 延長の待機中に `extend` で 3 秒を指定する
- **THEN** 延長を受け付けた時点から 3 秒後に回収され、`run` は非ゼロで終了する

#### Scenario: 待機中でない延長
- **WHEN** 1段階目を超える前、または延長を受け付けた後に `extend` を実行する
- **THEN** 延長は行われず、`extend` は非ゼロで終了する

### Requirement: 検証プロセスの回収
ペインがペイン専用の systemd scope に属する場合、回収はその scope に属するすべてのプロセスへ SIGKILL を送り、scope にプロセスが残らない状態で完了しなければならない。(SHALL)
ペイン専用の scope とは、ペインのために作られた `tmux-spawn-*.scope` のうち、tmux サーバとランナーを含まないものをいう。

ペイン専用の scope に属さない場合、回収は、ペインのセッション ID に属し、かつ開始時刻がペインの開始時刻以降のプロセスだけに SIGKILL を送らなければならない。(SHALL)
この場合、ペインより前に起動したプロセスと、他のセッションのプロセスを終了させてはならない。(SHALL)

検証コマンドから起動されたプロセスのうち、セッションから離脱し(setsid)、上記のどちらでも回収できなかったものは、残存として報告しなければならない。(SHALL)

ランナーが SIGINT、SIGTERM、SIGHUP のいずれかを受けた場合も、同じ回収を行ってから非ゼロで終了しなければならない。(SHALL)

#### Scenario: シグナルを無視するプロセスの回収
- **WHEN** ペインで `strace -f` により `sleep 300` を起動し、`tmux kill-session` で検証を終える
- **THEN** `run` の終了後、`strace` と `sleep` はどちらも残っていない

#### Scenario: ランナーの中断
- **WHEN** `run` の実行中に、ランナーへ SIGTERM を送る
- **THEN** ペインのプロセスは残らず、`run` は非ゼロで終了する

#### Scenario: ペインより前のプロセスを終了させない
- **WHEN** ペイン専用の scope が無い環境で、ペインより前に起動した同じユーザのプロセスがある状態で回収を行う
- **THEN** そのプロセスは回収後も生存している

#### Scenario: セッションから離脱したプロセス
- **WHEN** ペイン専用の scope が無い環境で、検証コマンドが setsid で別セッションの `sleep 300` を起動し、検証を終える
- **THEN** その `sleep` の PID が残存として出力され、`run` は非ゼロで終了する

### Requirement: PID 同一性の確認
ペイン専用の scope が無い場合の回収では、検証ランナーはシグナルを送る前に、記録したペインの PID と開始時刻を照合しなければならない。(SHALL)
記録した PID のプロセスが存在し、開始時刻が一致しない場合は、そのプロセスと、その PID をセッション ID に持つプロセスを終了させてはならない。そのうえで、PID が再利用されたことを出力しなければならない。(SHALL)

#### Scenario: PID 再利用時は終了させない
- **WHEN** ペイン専用の scope が無い環境で、記録した開始時刻が対象プロセスの開始時刻と一致しない状態で回収を行う
- **THEN** そのプロセスは終了せず、その PID が再利用されたことが出力される

### Requirement: 残存検査
検証ランナーは、実行記録を読み、プロセス・scope・一時パス・宣言したポートの残存を検査する `check` を持たなければならない。(SHALL)
`check` の検査対象は次のとおりとしなければならない。(SHALL)
- `--session` を指定した場合: その記録
- 指定しない場合: `run` が残存なしで完了した記録を除く、すべての記録

残存がある場合、`check` は残存ごとに、PID(またはパス、ポート)と理由を1行ずつ出力し、非ゼロで終了しなければならない。(SHALL)
残存がない場合、`check` は残存がないことを1行で出力し、終了コード 0 で終わらなければならない。(SHALL)
`check --prune` は、残存がないと確認できた記録だけを削除しなければならない。(SHALL)
systemd user session が無い環境では、`check` は記録した PID・セッション ID・一時パス・ポートを検査しなければならない。(SHALL)

#### Scenario: 残存ありの検出
- **WHEN** 実行記録に残るプロセスが生存したまま、`check` を実行する
- **THEN** その PID と理由が出力され、終了コードは非ゼロになる

#### Scenario: 残存なしの確認
- **WHEN** すべてのプロセスと一時パスが回収された後に、`check` を実行する
- **THEN** 残存がないことが1行で出力され、終了コードは 0 になる

#### Scenario: 記録の整理
- **WHEN** 残存のある記録と残存のない記録がある状態で、`check --prune` を実行する
- **THEN** 残存のない記録だけが削除され、残存のある記録は残る

### Requirement: 一時リソースの後始末
`--temp` を指定しない場合、`run` は専用の一時ディレクトリを作り、そのパスを環境変数 `SPIRITS_VERIFY_TMPDIR` で検証コマンドに渡さなければならない。(SHALL)
`run` は、自ら作った一時ディレクトリを、その配下のファイルを開いているプロセスが無いことを確認した後に削除しなければならない。(SHALL)
ファイルを開いているプロセスが残っている場合は削除せず、残存として報告しなければならない。(SHALL)
`--temp` で明示したディレクトリは削除してはならない。(SHALL)
`--port` で宣言したポートについて、`run` の終了時と `check` は待ち受け状態かどうかを確認し、待ち受け状態であれば残存として報告しなければならない。(SHALL)

#### Scenario: プロキシのポート解放
- **WHEN** `--port` でポートを宣言し、そのポートで待ち受けるローカルプロキシを起動する検証を実行して、検証を終える
- **THEN** プロキシのプロセスは残らず、宣言したポートは待ち受け状態ではなく、`run` が作った一時ディレクトリは削除されている

#### Scenario: 明示した一時ディレクトリ
- **WHEN** `--temp <dir>` を指定して検証を実行し、検証を終える
- **THEN** `<dir>` とその中身は残っている

#### Scenario: 開かれたままの一時ファイル
- **WHEN** ペイン専用の scope が無い環境で、setsid で離脱したプロセスが一時ディレクトリ内のファイルを開いたまま検証を終える
- **THEN** 一時ディレクトリは削除されず、そのプロセスの PID が残存として出力される

### Requirement: 回帰テストの CI 実行
CI は、tmux と strace を導入したうえで、検証ランナーのテストを実行しなければならない。(SHALL)
CI では、tmux または strace が無いことを理由にテストを skip し、成功として扱ってはならない。(SHALL)
CI は、検証ランナーとそのテストだけを変更した場合も実行されなければならない。(SHALL)

#### Scenario: CI でのテスト実行
- **WHEN** `scripts/tmux-verify.sh` だけを変更した pull request を作る
- **THEN** CI が起動し、tmux と strace を導入した環境でランナーのテストが実行される

#### Scenario: CI での依存の欠落
- **WHEN** CI の環境変数がある状態で、tmux または strace が無い環境でランナーのテストを実行する
- **THEN** テストは skip されず、非ゼロで終了する

### Requirement: 手順文書の更新
`.pi/skills/interactive-testing.md` は、tmux を使う対話検証の既定経路として、検証ランナーを記載しなければならない。(SHALL)
同文書は、次の項目を記載しなければならない。(SHALL)
- `run` をバックグラウンドで起動し、出力からセッション名を得る方法
- send-keys / capture-pane による操作
- `tmux kill-session` による終了
- 1段階目のタイムアウトの超過に気づく方法
- マシン環境に基づく2段階目の見積もりと、利用者に了解を求める手順
- `extend` の使い方
- 1段階目のタイムアウトの設定方法

同文書は、次の項目も記載しなければならない。(SHALL)
- 手動でペインを起動した場合の回収手順(SIGKILL を含む)
- scope の確認方法
- 手動で起動した検証は `check` で検出されないこと
- SIGHUP や SIGTERM を無視するプロセス種別

#### Scenario: 手順文書の内容
- **WHEN** `.pi/skills/interactive-testing.md` を確認する
- **THEN** 次の項目がそれぞれ記載されている
  - 既定経路としての検証ランナーと、そのバックグラウンド起動
  - タイムアウトの超過時の見積もりと了解の手順、および `extend`
  - 手動実行時の回収手順
  - シグナルを無視するプロセスの注意
