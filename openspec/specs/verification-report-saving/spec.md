# verification-report-saving Specification

## Purpose

OpenSpec の検証ステップが生んだ最終レポートを、検証対象として固定された変更のディレクトリへ衝突しない連番の完全なファイルとして保存し、保存されるまで検証を完了として扱わないことを保証する。保証は対話・非対話すべての実行モードで効く。

## Requirements

### Requirement: 検証ステップのあいだだけ保存手段を有効にする
システムは、検証ステップ（既定の検証と深い検証）が開かれたあいだだけ、検証レポートを保存する手段をモデルから見える状態にし、それ以外のあいだはモデルに見えない状態でなければならない。(SHALL) 保存手段が有効なあいだ、いつ使うかを示す指示をモデルへ渡す。(SHALL) ステップの終了は中断後の終了も含めて追跡し、終了した検証の保存手段は有効集合から外れる。(SHALL)

#### Scenario: 既定の検証が開かれる
- **GIVEN** 検証手段が無効なセッションで、既定の検証のコマンドが利用可能である
- **WHEN** 既定の検証を始める入力が送られた
- **THEN** 検証レポートの保存手段がモデルから見える状態になる

#### Scenario: 深い検証が開かれる
- **GIVEN** 検証手段が無効なセッションで、深い検証のコマンドが利用可能である
- **WHEN** 深い検証を始める入力が送られた
- **THEN** 検証レポートの保存手段がモデルから見える状態になる

#### Scenario: 検証ではないステップでは有効にならない
- **WHEN** 検証以外のステップを開く入力が送られた
- **THEN** 検証レポートの保存手段はモデルに見えないままになる

#### Scenario: ステップが終われば元に戻す
- **GIVEN** 検証ステップが開いて保存手段が有効になっている
- **WHEN** その検証ステップが終わった（中断後の終了を含む）
- **THEN** 保存手段はモデルから見えない状態に戻る

### Requirement: 検証対象は入力から固定し、モデルの申告では動かない
システムは、検証ステップを開いた入力と、対象が未固定のあいだに送られる後続ユーザー入力から、openspec の解決機構で一意に解決できる変更名を検証対象として固定しなければならない。(SHALL) 検証対象の固定はユーザー入力からのみ動き、モデルの申告では動かない。(MUST) 解決が一意でない名前（曖昧・部分一致・解決不能）では固定しない。一度固定した検証対象は、ステップ終了・セッション開始・ツリー移動まで動かさない。(MUST) 検証を開いた入力が store の指定を含む場合、対象の固定と保存は同じ store を使って解決しなければならない。(SHALL) 回答によって対象を固定できるのは、その検証ステップが回答の入力まで開いたまま続く場合に限る。(SHALL) 継続しない検証（深い検証）と、run が解決されないセッション（ルーティングが関与しないセッション）では、回答の入力そのものがステップを閉じるため固定できない (design Decision 14)。

#### Scenario: 変更名を伴って検証が開かれる
- **GIVEN** 解決できる変更名を伴って既定の検証が開かれた
- **WHEN** 検証レポートの保存が行われる
- **THEN** 保存先はその変更名の解決された変更ディレクトリになる

#### Scenario: 聞き返しへの回答で対象が固定される
- **GIVEN** 変更名の無い既定の検証が開かれ、検証対象が未固定で、その run は解決されて検証ステップが次の入力まで開いたまま続く
- **WHEN** 検証ステップのあいだに、解決できる変更名としてのユーザー入力が送られた
- **THEN** その変更が検証対象として固定され、以降の保存はその変更ディレクトリへ向かう

#### Scenario: 継続しない検証の聞き返しでは固定されない
- **GIVEN** 変更名の無い深い検証が開かれ、検証対象が未固定のまま run が聞き返しで終わった
- **WHEN** その後の入力が解決できる変更名を指定した
- **THEN** 検証対象は固定されず、保存手段は有効集合に戻らない

#### Scenario: 解決できない回答では固定されない
- **GIVEN** 検証対象が未固定である
- **WHEN** 変更名として解決できないユーザー入力が送られた
- **THEN** 検証対象は未固定のままになる

#### Scenario: 固定された後は対象が動かない
- **GIVEN** 検証対象が変更 A として固定され、検証ステップが開いており、変更 B も解決可能である
- **WHEN** 検証ステップのあいだに変更 B の名前としてのユーザー入力が送られ、その後で検証レポートの保存が行われた
- **THEN** 検証対象は変更 A のままで、保存先は変更 A のディレクトリになる

#### Scenario: store 指定時は同じ store で対象を固定する
- **GIVEN** 検証を開いた入力が store の指定を含み、検証対象が未固定である
- **WHEN** 後続のユーザー入力が、その store だけに存在する変更名を完全一致で指定した
- **THEN** 一覧取得にもその store 指定が渡り、その変更が検証対象として固定される

#### Scenario: store 指定時はローカルだけの変更を固定しない
- **GIVEN** 検証を開いた入力が store の指定を含む
- **WHEN** 後続のユーザー入力が、ローカルには存在するが指定 store には存在しない変更名を指定した
- **THEN** 検証対象は未固定のままになる

### Requirement: 検証が有効でない保存要求は書き込み前に拒否する
保存手段が有効な集合に入っていても、検証ステップが開いていないか検証対象が未固定のときに保存要求があれば、システムは書き込まずに理由を返さなければならない。(MUST)

#### Scenario: 検証ステップが開いていない呼び出し
- **GIVEN** 何らかの経路で保存手段が有効集合に入っているが、検証ステップは開いていない
- **WHEN** 本文を渡して保存が要求された
- **THEN** 書き込みは行われず、検証中ではないことを示す理由が返る

#### Scenario: 対象が未固定の呼び出し
- **GIVEN** 検証ステップが開いているが、検証対象が未固定である
- **WHEN** 本文を渡して保存が要求された
- **THEN** 書き込みは行われず、検証対象が未確定であることを示す理由が返る

#### Scenario: 未固定の拒否理由を開き直しでも案内する
- **GIVEN** 検証ステップが開いているが検証対象が未固定で、この run のあとでは回答による固定もできない
- **WHEN** 本文を渡して保存が要求された
- **THEN** 書き込みは行われず、返す理由は回答で固定できる場合の聞き返しと、変更名を付けて検証を開き直す方法の双方を案内する

### Requirement: 検証種別ごとの連番でファイル名を決める
システムは、検証レポートを検証種別ごとに決まった連番のファイル名で保存しなければならない。(SHALL) 検証種別は実行中の検証ステップから決め、モデルの申告では変えない。(MUST) 連番は、保存先ディレクトリに存在する同じ系列のファイルの最大値に 1 を加えた値とし、系列にファイルが無い場合は 1 とする。(SHALL) 既定の検証の系列は `verify<N>.md`、深い検証の系列は `d-verify<N>.md` とする。(SHALL)

#### Scenario: 同じ系列のファイルが無い
- **GIVEN** 対象変更のディレクトリに検証レポートが 1 つも無い
- **WHEN** 既定の検証のレポートを保存する
- **THEN** `verify1.md` として保存される

#### Scenario: 同じ系列のファイルが既にある
- **GIVEN** 対象変更のディレクトリに `verify1.md` と `verify2.md` がある
- **WHEN** 既定の検証のレポートを保存する
- **THEN** `verify3.md` として保存される

#### Scenario: 欠番は埋めない
- **GIVEN** 対象変更のディレクトリに `verify1.md` と `verify3.md` があり、`verify2.md` は無い
- **WHEN** 既定の検証のレポートを保存する
- **THEN** `verify4.md` として保存される

#### Scenario: 深い検証は別の系列を使う
- **GIVEN** 対象変更のディレクトリに `verify1.md` がある
- **WHEN** 深い検証のレポートを保存する
- **THEN** `d-verify1.md` として保存される

### Requirement: 既存のファイルを上書きせず、完全な本文だけを残す
システムは、検証レポートの保存ごとに新しいファイルを作成し、既存のファイルの内容を変更してはならない。(MUST) 検証対象のディレクトリには、解決された変更ディレクトリの直下のレポート系列名で作成する。(SHALL) 保存の結果として最終名に観測されるファイルは、要求された本文と一致する完全な内容か、存在しないかのどちらかでなければならない。(MUST) 連番を決めた後にその名前が他の実行で使われていた場合は、次の連番で再試行し、上限を超えた場合は失敗を返す。(SHALL)

#### Scenario: 同じ連番を巡る競合
- **GIVEN** 保存する連番を決めた直後に、同じ名前のファイルが別の実行で作られた
- **WHEN** 作成が失敗した
- **THEN** 次の連番でファイルを作成し、先に作られたファイルの内容は変わらない

#### Scenario: 既存レポートはそのまま残る
- **GIVEN** 対象変更のディレクトリに `verify1.md` が既にある
- **WHEN** 検証レポートを保存する
- **THEN** `verify1.md` の内容は変更されず、新しい番号のファイルが作られる

#### Scenario: 書き込みが失敗した部分是残さない
- **GIVEN** 保存の途中で書き込みが失敗した
- **WHEN** 保存結果を見る
- **THEN** 最終名のファイルは存在せず、部分内容のレポートは残らない

### Requirement: 保存の受理と応答
システムは、検証対象として固定された変更を openspec の解決機構で解決し、その変更ディレクトリへ渡された本文を書き込み、成功時には保存先のパスを、失敗時には理由を返さなければならない。(SHALL) 保存手段が受け取るのは検証レポートの本文だけとし、変更名・保存先・ファイル名は受け取らない。(MUST) 空または空白のみの本文は受け付けない。(MUST) 変更を解決できない場合、または保存先ディレクトリの採番・作成で I/O が失敗した場合は、書き込まずに理由を返す。(MUST) 検証を開いた入力が store の指定を含むときは、名前の有無や固定のされ方にかかわらずその store 指定を保持し、解決にも渡す。(SHALL)

#### Scenario: 固定された変更への保存
- **GIVEN** 検証対象が解決できる変更名として固定されている
- **WHEN** 検証レポートの本文を渡して保存した
- **THEN** その変更ディレクトリ直下の保存先パスが返る

#### Scenario: 解決できない変更名の検証
- **WHEN** 検証対象の変更名が解決できない状態で保存した
- **THEN** 何も書き込まず、解決できなかったことを示す理由が返る

#### Scenario: store 指定を伴う検証の保存
- **GIVEN** 検証を開いた入力が store の指定を含み、検証対象が固定されている
- **WHEN** 検証レポートの本文を渡して保存した
- **THEN** 解決にはその store 指定が渡され、解決された変更ディレクトリ直下の保存先パスが返る

#### Scenario: 検証を開いた行に store 指定だけがある場合
- **GIVEN** 検証を開いた入力が store の指定を含むが変更名を含まず、後続の入力で検証対象が固定された
- **WHEN** 検証レポートの本文を渡して保存した
- **THEN** 解決には開行の store 指定が渡される

#### Scenario: 空の本文
- **WHEN** 空または空白のみの本文を渡して保存した
- **THEN** 書き込まないように拒否し、理由を返す

#### Scenario: 採番前に保存先ディレクトリが消えている
- **GIVEN** 検証対象は固定され、保存先ディレクトリが採番の直前に存在しなくなった
- **WHEN** 検証レポートの本文を渡して保存した
- **THEN** 例外を送出せず、保存できなかった理由を返す

#### Scenario: 一時ファイル作成後の書き込みが失敗する
- **GIVEN** 保存先ディレクトリで一時ファイルの作成後に本文の書き込みが失敗した
- **WHEN** 保存結果を見る
- **THEN** 最終名も一時ファイルも残らず、保存できなかった理由が返る

### Requirement: 保存されるまで検証を完了として扱わない
システムは、検証対象が固定された検証ステップの開かれた run が保存なしに終わろうとしたとき、1 度だけ保存を要求して継続しなければならない。(SHALL) 要求の後も保存されない場合は、検証レポートが保存されていないことを利用者に通知し、それ以上要求してはならない。(MUST) 検証対象が未固定（モデルが利用者に確認を求めて待っている）まま run が終わり、その検証ステップが次の入力まで開いたまま続く場合は、継続要求を行わず、保存手段の有効化と督促の回数を維持したまま次の入力を待つ。(SHALL) 継続しないステップがその run で閉じるときは「検証ステップのあいだだけ保存手段を有効にする」が優先し、保存手段は有効集合から外れて「対象を固定できないまま終わった検証を伝える」が扱う。

#### Scenario: 未保存で run が終わろうとする
- **GIVEN** 検証ステップが開かれ、検証対象は固定済みで、まだレポートが保存されていない
- **WHEN** その run が終わろうとした
- **THEN** 保存を要求する 1 回の継続が行われ、run は終わらない

#### Scenario: 督促の後も保存されない
- **GIVEN** 保存を要求する継続が 1 回行われ、その run でも保存されなかった
- **WHEN** 再び run が終わろうとした
- **THEN** 継続を要求せず、未保存である旨を利用者に通知する

#### Scenario: 保存済みなら督促しない
- **GIVEN** 検証ステップが開かれ、そのレポートは既に保存されている
- **WHEN** その run が終わろうとした
- **THEN** 継続を要求せず、未保存の通知もしない

#### Scenario: 継続しない検証の終了は督促ではなく通知が扱う
- **GIVEN** 変更名の無い深い検証が開かれ、検証対象が未固定である
- **WHEN** その run が settle した
- **THEN** 継続要求は一切行わず、保存手段は有効集合から外れ、「対象を固定できないまま終わった検証を伝える」の通知が行われる

#### Scenario: 中断した run では督促しない
- **GIVEN** 検証ステップが開かれ、まだレポートが保存されていない
- **WHEN** 利用者が run を中断した
- **THEN** 保存を要求する継続を行わない

#### Scenario: 対象未固定の聞き返しでは督促しない
- **GIVEN** 検証ステップが開いているが検証対象が未固定で、モデルが変更名をユーザーに尋ねて終わろうとしている
- **WHEN** その run が終わろうとした
- **THEN** 保存を要求する継続を行わず、保存手段は有効なまま次の入力を待つ

### Requirement: 督促の境界と通知の経路
システムは、検証レポートの保存保証を実行モードに関係なく提供する。(SHALL) 保存を要求する継続は、利用者が応答できるセッション（対話モードと RPC）でのみ行い、それ以外のセッションでは継続を要求せず通知だけを行う。(SHALL) 通知は、実行モードの標準出力の出力形式を変えない経路で行う。(MUST) 実行環境の再読み込みやセッションの再開で復帰した検証ステップでは、督促を行わない。

#### Scenario: 非対話のセッション
- **GIVEN** 利用者が応答できない実行モードで検証ステップが開いている
- **WHEN** レポートが保存されないまま run が終わろうとした
- **THEN** 継続を要求せず、未保存である旨を標準出力の出力形式を変えない経路で通知する

#### Scenario: 非対話でも保存は同じ規則で効く
- **GIVEN** 利用者が応答できない実行モードで検証ステップが開かれ、検証対象が固定されている
- **WHEN** 検証レポートの保存が行われた
- **THEN** 対話モードと同じ連番規則と衝突防止で保存され、保存先が返る

#### Scenario: 再読み込みで復帰した検証ステップ
- **GIVEN** 検証ステップが開いたセッションで実行環境が再読み込みされ、そのステップが復帰した
- **WHEN** 復帰後の run が終わろうとした
- **THEN** 保存を要求する継続を行わない

### Requirement: 対象を固定できないまま終わった検証を伝える
システムは、検証対象が未固定のまま検証ステップが終わり、かつレポートが保存されていないとき、レポートが保存されていないことと、変更名を付けて検証を開き直す方法を、検証ごとに 1 回だけ利用者へ伝えなければならない。(SHALL) 対話できるセッションでは利用者に伝えられる手段で、それ以外のセッションでは実行モードの標準出力の出力形式を変えない経路で行う。(SHALL) 同じ検証に対してこの通知は 1 回を超えて行わない。(SHALL) 対象が固定されている検証はこの通知の対象外とし、その未保存は「保存されるまで検証を完了として扱わない」が見る。(SHALL) 検証ステップが終わったとき、システムはその検証の「開かれたが保存していない」状態を、通知を行ったか否か・対象が固定されていたか否か・中断されたか否かにかかわらず必ず消費する。(SHALL) 消費された状態は後続の入力からこの通知を生じさせない。(SHALL)

#### Scenario: 深い検証の聞き返しのあとの settle
- **GIVEN** 変更名の無い深い検証が開かれ、検証対象が未固定のまま run はどの変更名かを聞き返して終わった
- **WHEN** その run が settle して検証ステップが閉じた
- **THEN** 保存手段は有効集合から外れ、レポートが保存されていないことと変更名を付けて開き直す方法が 1 回伝えられ、後続の入力は対象を固定しない

#### Scenario: 解決されない run のあとの入力でステップが閉じるとき
- **GIVEN** 変更名の無い既定の検証が開き、その run は解決されず（ルーティングが関与しないセッション）、ステップが開いたまま settle した
- **WHEN** 聞き返しへの回答としての入力が送られ、検証ステップが閉じた
- **THEN** 保存手段は有効集合から外れ、対象は固定されず、レポートが保存されていないことと開き直しが 1 回伝えられる

#### Scenario: 未固定の検証を同じ検証または深い検証で開き直す
- **GIVEN** 変更名なしで開いた既定の検証が未固定・未保存のまま、次の入力を待っている
- **WHEN** 利用者が解決可能な変更名を付けて既定の検証を再度開始するか、深い検証を開始する
- **THEN** どちらの場合も旧検証の未保存と開き直し方を 1 回だけ伝え、新しい検証は指定された変更を固定し、自分の系列でその変更のディレクトリへ保存できる

#### Scenario: 非対話では標準エラーで伝える
- **GIVEN** `print` / `json` のセッションで、上記のいずれかが起きた
- **WHEN** 通知の時刻が来た
- **THEN** 継続要求は一切行わず、標準エラーへ同じ事実が書かれ、標準出力の出力形式は変わらない

#### Scenario: 伝えない終了
- **GIVEN** 検証ステップが終わりつつある
- **WHEN** run が中断された、またはセッションが開始・ツリー移動した、またはレポートは保存済みである
- **THEN** この通知は行わない（中断では督促と同じ理由で、セッションの変更では再開した run を督促しないのと同じ理由で静かにする）

#### Scenario: 固定された検証の終了が後日の通知にならない
- **GIVEN** 検証対象を固定した検証ステップが、レポートを保存しないまま終わった（中断、または別コマンドでワークフローを抜けた）
- **WHEN** その検証と無関係な後続の入力が送られた
- **THEN** この通知は行わず、後続の入力が検証対象を固定することも保存手段を有効にすることもない

### Requirement: 検証プロンプトの再生成に依存しない
OpenSpec CLI が生成する検証プロンプトや、同梱スキルの本文が書き換えられた後も、検証レポートの保存と未保存時の督促は従来どおり効かなければならない。(SHALL)

#### Scenario: 検証プロンプトが再生成される
- **GIVEN** 既定の検証のプロンプトが OpenSpec CLI の更新で別本文に書き換えられ、その本文が実際に展開される
- **WHEN** 既定の検証を走らせてレポートが保存されないまま run が終わろうとした
- **THEN** 保存要求は従来どおり 1 回行われる

### Requirement: 後段フェーズ機能への非依存
検証レポートの保存は、M5（Phase 2）の機能を import・参照してはならない。(MUST)

#### Scenario: 層の検査が通る
- **WHEN** アーキテクチャ規約の検査を実行する
- **THEN** 検証レポートの保存を置く層から M5 の機能への依存は報告されない
