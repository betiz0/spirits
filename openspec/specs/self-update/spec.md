# self-update Specification

## Purpose

インストール済みの spirits 実行ファイルを、CLI の `spirits update` だけで最新の stable リリースへ安全に置き換えられるようにする。版の解決、チェックサム検証、原子的な置換、一時ファイルの後始末、失敗時の案内、拡張更新との組み合わせを定める。

## Requirements

### Requirement: spirits update による自己更新
コンパイル済み `spirits` は、`update` の引数が pi の `update` の文法で対象を self と解釈され、かつエラーにならない場合、実行ファイル自身を最新の stable リリースへ置き換えなければならない。(SHALL)
対象となる形は `update`、`update self`、`update pi`、`update --self`、およびこれらに `--force`、`-a` / `--approve`、`-na` / `--no-approve` を加えた形である。

#### Scenario: 最新版への更新
- **WHEN** 0.2.0 がインストール済みの環境で最新 stable が 0.3.0 のとき `spirits update` を実行する
- **THEN** 実行ファイルは 0.3.0 に置き換わり、終了コードは 0 になる

#### Scenario: project trust 指定付きの自己更新
- **WHEN** 0.2.0 がインストール済みの環境で最新 stable が 0.3.0 のとき `spirits update -a` を実行する
- **THEN** 実行ファイルは 0.3.0 に置き換わり、終了コードは 0 になる

### Requirement: 自己更新の版比較
インストール済みバージョンが解決された最新版と等しく、`--force` が指定されていない場合、自己更新は置換を行わず、最新である旨を表示して終了コード 0 で終わらなければならない。(SHALL)
インストール済みバージョンが解決された最新版より新しく(prerelease ビルドなど)、`--force` が指定されていない場合、自己更新は置換を行わず、stable の最新版より新しいバージョンである旨を表示して終了コード 0 で終わらなければならない。(SHALL)
`--force` が指定された場合、インストール済みバージョンが最新版と等しい場合も新しい場合も、自己更新は最新版のダウンロードと置換を実行しなければならない。(SHALL)

#### Scenario: 最新時の置換なし
- **WHEN** 0.3.0 がインストール済みの環境で最新 stable が 0.3.0 のとき `spirits update` を実行する
- **THEN** 実行ファイルは変更されず、最新である旨が表示され、終了コードは 0 になる

#### Scenario: --force による再取得
- **WHEN** 0.3.0 がインストール済みの環境で最新 stable が 0.3.0 のとき `spirits update --force` を実行する
- **THEN** 成果物がダウンロードされ、実行ファイルは検証済みの 0.3.0 で置き換えられる

#### Scenario: 最新より新しい場合
- **WHEN** 0.4.0-rc.1 がインストール済みの環境で最新 stable が 0.3.0 のとき `spirits update` を実行する
- **THEN** 実行ファイルは変更されず、stable の最新版より新しいバージョンである旨が表示され、終了コードは 0 になる

#### Scenario: --force による stable への置換
- **WHEN** 0.4.0-rc.1 がインストール済みの環境で最新 stable が 0.3.0 のとき `spirits update --force` を実行する
- **THEN** 実行ファイルは検証済みの 0.3.0 で置き換えられ、終了コードは 0 になる

### Requirement: 自己更新のリリース解決と検証
自己更新は、`VERSION` を指定しないインストーラと同じ規則で最新版を解決しなければならない。すなわち、Releases API が返す作成日時の新しい順の一覧(1 ページ 100 件)から、draft と prerelease を除いた `spirits-v*` タグのリリースの先頭を最新として使わなければならない。(SHALL)
自己更新は、解決したリリースの `spirits-linux-x64` と `spirits-linux-x64.sha256` を取得し、配置前にチェックサムを検証しなければならない。(SHALL)
チェックサム検証に失敗した場合、インストール済みの実行ファイルを変更せず、非ゼロで終了しなければならない。(MUST)

#### Scenario: prerelease と pi リリースの除外
- **WHEN** `spirits-v0.3.0` より新しい prerelease の `spirits-v0.4.0-rc.1` と、pi のリリース `v1.0.0` がある環境で `spirits update` を実行する
- **THEN** `spirits-v0.3.0` の成果物が更新対象になる

#### Scenario: チェックサム不一致
- **WHEN** ダウンロードされる実行ファイルが `.sha256` と一致しない状態で `spirits update` を実行する
- **THEN** 終了コードは非ゼロになり、インストール済みの実行ファイルは元の内容のまま残る

#### Scenario: stable リリース未検出
- **WHEN** 通常の(draft でも prerelease でもない)`spirits-v*` リリースが存在しない状態で `spirits update` を実行する
- **THEN** 解決に失敗した旨が表示され、終了コードは非ゼロになり、実行ファイルは変更されない

### Requirement: 自己更新の原子性
自己更新は、置換のどの時点でも、インストール先のパスが元の実行ファイル全体か、検証済みの新しい実行ファイル全体のいずれかになるように置換しなければならない。(SHALL)
置換が完了するまで、インストール済みの実行ファイルは元の内容と実行ビットを保たなければならない。(SHALL)
置換後の実行ファイルは実行ビットを持たなければならない。(SHALL)
複数の自己更新、または自己更新とインストーラが同時に実行された場合も、インストール先はいずれかの実行が配置した検証済みの実行ファイル全体でなければならない。(SHALL)

#### Scenario: 成功時の置換
- **WHEN** チェックサム検証済みの自己更新が完了する
- **THEN** インストール先の実行ファイルは新しい内容で実行ビットを持ち、次回起動から新しいバージョンが使われる

#### Scenario: 置換失敗時の元ファイル維持
- **WHEN** インストール先ディレクトリへの書き込みが置換の完了前に失敗する
- **THEN** 終了コードは非ゼロになり、インストール済みの実行ファイルは元の内容と実行ビットを保つ

#### Scenario: 同時実行
- **WHEN** 同じインストール先に対して 2 つの `spirits update --force` を同時に実行する
- **THEN** 両方の終了後、インストール先は検証済みの実行ファイル全体で、実行ビットを持つ

### Requirement: 自己更新の一時ファイルの後始末
自己更新は、失敗した場合、および SIGINT または SIGTERM を受けて中断した場合、自身が作成した一時ファイルを削除して非ゼロで終了しなければならない。(SHALL)
自己更新は、実行環境の拒否判定(未コンパイル実行、非対応プラットフォーム、配置先ディレクトリの書き込み不可、`PI_OFFLINE`)をすべて通過した後、最新リリースの解決より前に、インストール先ディレクトリに残っている過去の自己更新またはインストーラの一時ファイルを削除しなければならない。(SHALL)
実行中の別の自己更新またはインストーラが使用している一時ファイルは削除してはならない。(MUST)

#### Scenario: 失敗時の削除
- **WHEN** チェックサム不一致で自己更新が失敗する
- **THEN** インストール先ディレクトリに自己更新の一時ファイルは残らない

#### Scenario: SIGINT による中断
- **WHEN** ダウンロード中の `spirits update` に SIGINT を送る
- **THEN** 終了コードは非ゼロになり、インストール済みの実行ファイルは元の内容と実行ビットを保ち、一時ファイルは残らない

#### Scenario: 残った一時ファイルの削除
- **WHEN** 既に終了したプロセスが残した一時ファイルがインストール先ディレクトリにある状態で `spirits update` を実行する
- **THEN** その一時ファイルは削除される

#### Scenario: 最新版での残骸削除
- **WHEN** インストール済みバージョンが最新 stable と等しく、終了済みプロセスが残した一時ファイルがインストール先ディレクトリにある状態で `spirits update` を実行する
- **THEN** その一時ファイルは削除され、最新である旨が表示され、終了コードは 0 になる

#### Scenario: 実行中の一時ファイルの保護
- **WHEN** 実行中の別のインストーラが使用している一時ファイルがインストール先ディレクトリにある状態で `spirits update` を実行する
- **THEN** その一時ファイルは削除されない

### Requirement: 自己更新できない環境での案内
コンパイルされていない実行、Linux x86_64 以外、配置先ディレクトリが書き込み不可の場合、自己更新は実行ファイルを変更せず、理由とインストーラ再実行の手段を表示して非ゼロで終了しなければならない。(SHALL)
環境変数 `PI_OFFLINE` が有効(`1`、`true`、`yes` のいずれか。`true` と `yes` は大文字小文字を区別しない)な場合、自己更新はネットワークアクセスを行わず、実行ファイルを変更せず、オフライン指定のため更新しない旨と、`PI_OFFLINE` を解除して再実行する手段を表示して非ゼロで終了しなければならない。(SHALL)
リリース解決、ダウンロード、または無通信タイムアウトで失敗した場合、自己更新は実行ファイルを変更せず、失敗の理由とインストーラ再実行の手段を表示して非ゼロで終了しなければならない。(SHALL)

#### Scenario: 未コンパイル実行
- **WHEN** ソースから `bun packages/spirits/bin/spirits.ts update` を実行する
- **THEN** 自己更新は実行されず、ソース実行では更新できない旨とインストーラ再実行の手段が表示され、終了コードは非ゼロになる

#### Scenario: 書き込み不可
- **WHEN** インストール先ディレクトリが書き込み不可の状態で `spirits update` を実行する
- **THEN** 実行ファイルは変更されず、書き込み不可である旨とインストーラ再実行の手段が表示され、終了コードは非ゼロになる

#### Scenario: 最新版で書き込み不可
- **WHEN** インストール済みバージョンが最新 stable と等しく、インストール先ディレクトリが書き込み不可の状態で `spirits update` を実行する
- **THEN** 実行ファイルは変更されず、書き込み不可である旨とインストーラ再実行の手段が表示され、終了コードは非ゼロになる

#### Scenario: オフライン指定
- **WHEN** `PI_OFFLINE=1` を設定して `spirits update` を実行する
- **THEN** Releases API への要求は発生せず、実行ファイルは変更されず、オフライン指定のため更新しない旨と `PI_OFFLINE` を解除して再実行する手段が表示され、終了コードは非ゼロになる

#### Scenario: ネットワーク失敗
- **WHEN** Releases API へ到達できない状態で `spirits update` を実行する
- **THEN** 実行ファイルは変更されず、失敗の理由とインストーラ再実行の手段が表示され、終了コードは非ゼロになる

### Requirement: 自己更新の無通信タイムアウト
自己更新は、Releases API への要求と成果物のダウンロードのそれぞれで、要求の送信後、または最後にデータを受信してから、データを受信しない状態が上限時間続いた場合、その要求を失敗として扱わなければならない。(SHALL)
データの受信が続いている間は、要求全体の所要時間が上限時間を超えても失敗として扱ってはならない。(MUST)
上限時間の既定値は 10 秒とし、環境変数 `SPIRITS_UPDATE_IDLE_TIMEOUT_SECONDS` に正の整数が設定されていれば、その秒数を上限時間として使わなければならない。(SHALL)
`SPIRITS_UPDATE_IDLE_TIMEOUT_SECONDS` が未設定、または正の整数でない場合は、既定値を使わなければならない。(SHALL)

#### Scenario: 応答の停止
- **WHEN** `SPIRITS_UPDATE_IDLE_TIMEOUT_SECONDS` を設定せず `spirits update` を実行し、ダウンロード中にサーバがデータの送信を止めたまま 10 秒が経過する
- **THEN** 無通信タイムアウトである旨とインストーラ再実行の手段が表示され、実行ファイルは変更されず、終了コードは非ゼロになる

#### Scenario: 上限時間の上書き
- **WHEN** `SPIRITS_UPDATE_IDLE_TIMEOUT_SECONDS=2` を設定して `spirits update` を実行し、Releases API がデータを返さないまま 2 秒が経過する
- **THEN** その時点で要求は失敗として扱われ、終了コードは非ゼロになる

#### Scenario: 低速でも受信が続く場合
- **WHEN** 上限時間より短い間隔でデータを送り続け、全体では上限時間より長くかかるダウンロードで `spirits update` を実行する
- **THEN** タイムアウトにはならず、自己更新は完了する

#### Scenario: 不正な上書き値
- **WHEN** `SPIRITS_UPDATE_IDLE_TIMEOUT_SECONDS` に `0`、`-1`、`1.5`、`abc` のいずれかを設定して `spirits update` を実行する
- **THEN** 上限時間は既定の 10 秒になる

### Requirement: pi へ渡す update 引数
`update` の引数のうち、次の形は自己更新を行わず、pi の既存の処理へそのまま渡さなければならない。(SHALL)
- pi の `update` の文法で、対象が拡張だけ、モデルだけ、または単一のソースになる形(`--extensions`、`--models`、`--extension <source>`、`self` / `pi` 以外の位置引数)
- `-h` / `--help` を含む形
- pi がエラーとする形(未知のオプション、余分な引数、値の欠落、両立しないオプションの組み合わせ)

#### Scenario: 拡張更新の透過
- **WHEN** コンパイル済み `spirits update --extensions` を実行する
- **THEN** pi の拡張更新処理がそのまま実行され、spirits 自身の置換は行われない

#### Scenario: 不正な組み合わせの透過
- **WHEN** コンパイル済み `spirits update --all --self` を実行する
- **THEN** pi のオプション組み合わせのエラーが表示され、自己更新は行われず、終了コードは非ゼロになる

### Requirement: 自己更新と拡張更新の組み合わせ
pi の `update` の文法で対象が all になる形では、自己更新を先に行い、自己更新が成功した後(置換せずに終了コード 0 で終わった場合を含む)、インストール先の実行ファイルで `update --extensions` を実行し、その終了コードを返さなければならない。(SHALL)
対象となる形は `update --all`、`update --self --extensions`、`update self --extensions`、`update pi --extensions`、およびこれらに `--force`、`-a` / `--approve`、`-na` / `--no-approve` を加えた形である。
組み合わせた拡張更新には、指定された `-a` / `--approve` / `-na` / `--no-approve` を引き継がなければならない。(SHALL)
自己更新が失敗した場合、組み合わせた拡張更新を実行してはならない。(MUST)

#### Scenario: --all の順序
- **WHEN** コンパイル済み `spirits update --all` を実行し、自己更新が成功する
- **THEN** 更新後の実行ファイルで `update --extensions` が実行され、その終了コードが返る

#### Scenario: 最新時の --all
- **WHEN** インストール済みバージョンが最新 stable と等しい状態で `spirits update --all` を実行する
- **THEN** 実行ファイルは変更されず、インストール先の実行ファイルで `update --extensions` が実行され、その終了コードが返る

#### Scenario: project trust 指定の引き継ぎ
- **WHEN** `spirits update --all -a` を実行し、自己更新が成功する
- **THEN** 拡張更新は `update --extensions -a` として実行される

#### Scenario: 自己更新失敗時に拡張更新しない
- **WHEN** `spirits update --all` を実行し、自己更新が失敗する
- **THEN** 拡張更新は実行されず、終了コードは非ゼロになる

### Requirement: 後段フェーズ機能への非依存
自己更新は、M3 以降の機能(rlm、Continual Harness、Phase 2)を import・参照してはならない。(MUST)

#### Scenario: 後段機能の非参照
- **WHEN** 自己更新の実装の参照を列挙する
- **THEN** rlm / harness / phase2 のモジュールやコマンドへの参照が存在しない
