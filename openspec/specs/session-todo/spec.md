# session-todo Specification

## Purpose

Provide a session-bound TODO list that the LLM manages through an explicit tool, shown in a panel at the bottom of the interactive screen, so users can track task progress across agent turns without losing it when the session or branch changes.

## Requirements

### Requirement: TODO は現在のセッションの現在のブランチに紐づく
システムは TODO 状態を、現在のセッションの現在のブランチ上で最後に保存された状態として解決しなければならない。(SHALL)

#### Scenario: 別セッションへの切り替え
- **GIVEN** セッション A に未完了の TODO「A1」があり、セッション B には TODO が無い
- **WHEN** ユーザーが `/resume` でセッション B に切り替える
- **THEN** TODO パネルは非表示になり、続く `manage_todos` の結果にも「A1」は含まれない

#### Scenario: `/tree` によるブランチ移動
- **GIVEN** 分岐点の後、ブランチ X で TODO「X1」が追加され、ブランチ Y では TODO が追加されていない
- **WHEN** ユーザーが `/tree` で Y の末端へ移動し、その後 X の末端へ戻る
- **THEN** Y へ移動した時点でパネルは非表示になり、X へ戻った時点で「X1」が再表示される

#### Scenario: fork による引き継ぎ
- **GIVEN** 未完了の TODO「F1」が保存された後の位置がある
- **WHEN** ユーザーがその位置から fork する
- **THEN** fork 先のセッションのパネルに「F1」が表示される

### Requirement: LLM はツールで TODO を管理する
システムは LLM が呼び出せる `manage_todos` ツールを全実行モード(interactive、print、RPC)で提供しなければならない。ツールは 1 回の呼び出しで、追加・テキスト更新・完了状態の変更・削除の操作を複数受け付け、指定順に適用しなければならない。(SHALL)

#### Scenario: 項目の追加と ID の採番
- **GIVEN** 現在のブランチに TODO が無い
- **WHEN** LLM が `manage_todos` でテキスト「Fix bug」と「Write test」の追加を 1 回で指示する
- **THEN** 2 項目が未完了として保存され、ID 1 と 2 がこの順に割り当てられ、ツール結果に ID・テキスト・完了状態を含む全項目が返る

#### Scenario: 削除した ID は再利用されない
- **GIVEN** ID 1 と 2 の項目があり、ID 2 を削除した
- **WHEN** LLM が新しい項目の追加を指示する
- **THEN** 新しい項目には ID 3 が割り当てられる

#### Scenario: 項目の完了と再開
- **GIVEN** 未完了の項目 ID 1 がある
- **WHEN** LLM が ID 1 を完了にし、別の呼び出しで未完了に戻す
- **THEN** 1 回目の後は完了状態、2 回目の後は未完了状態として保存され、パネルもそれに従う

#### Scenario: テキストの更新
- **WHEN** LLM が既存項目 ID 1 のテキストを「Fix login bug」に更新する
- **THEN** ID 1 のテキストだけが変わり、ID と完了状態は変わらない

#### Scenario: 項目の削除
- **WHEN** LLM が既存項目 ID 1 の削除を指示する
- **THEN** ID 1 は現在の TODO から消え、パネルからも消える

#### Scenario: print モードでの利用
- **WHEN** print モードで LLM が `manage_todos` で項目を追加する
- **THEN** 項目はセッションに保存され、同じセッションを対話 TUI で再開するとパネルに表示される

### Requirement: 不正な操作を含む呼び出しは何も適用しない
システムは `manage_todos` の 1 回の呼び出しに不正な操作が 1 つでも含まれる場合、その呼び出しのどの操作も適用せず、エラーとして結果を返さなければならない。結果には不正な操作の位置と理由を含めなければならない。(SHALL)

不正な操作は次のとおりとする。
- 存在しない ID の更新・削除。同じ呼び出しの前の操作で削除された ID を含む
- 空文字列または空白だけのテキストによる追加・更新
- テキストも完了状態も指定しない更新
- 操作が 0 件の呼び出し

#### Scenario: 存在しない ID を含む呼び出し
- **GIVEN** 未完了の項目 ID 1 だけがある
- **WHEN** LLM が 1 回の呼び出しで「ID 1 を完了」「ID 9 を削除」を指示する
- **THEN** エラー結果が返り、2 番目の操作で ID 9 が存在しないことが示され、ID 1 は未完了のまま残る

#### Scenario: 空白だけのテキスト
- **WHEN** LLM が「   」を追加する
- **THEN** エラー結果が返り、項目は追加されず、次に追加される項目の ID も変わらない

#### Scenario: 操作が 0 件
- **WHEN** LLM が操作の配列を空にして呼び出す
- **THEN** エラー結果が返り、TODO 状態は変わらない

### Requirement: TODO パネルはエディタとフッターの間に表示される
システムは対話 TUI で、エディタとフッターの間に TODO パネルを表示しなければならない。パネルが展開されているときは、次の規則に従わなければならない。(SHALL)
- 未完了項目を ID の昇順で 1 項目 1 行として、最大 N 行まで表示する
- 表示しきれない未完了項目の件数と完了項目の件数は、項目行の後の 1 行に件数だけを表示する。完了項目は個別には表示しない
- 項目が 1 件以上あり、すべて完了しているときは「all done」を含む 1 行だけを表示する
- 項目が 0 件のときはパネルを表示しない
- 各行は端末幅に収まるように切り詰める

N の既定値は 5 とする。環境変数 `SPIRITS_TODO_MAX_LINES` に正の整数を指定すると N を変更できる。正の整数でない値は既定値として扱う。print / RPC モードではパネルを表示しない。

#### Scenario: 未完了と完了が混在する
- **GIVEN** N=5、パネルが展開されていて、未完了 3 件、完了 2 件
- **WHEN** パネルが描画される
- **THEN** 未完了 3 件がそれぞれ 1 行で表示され、続く 1 行に完了 2 件が件数で表示される

#### Scenario: 未完了が上限を超える
- **GIVEN** N=5、パネルが展開されていて、未完了 7 件(ID 1〜7)、完了 0 件
- **WHEN** パネルが描画される
- **THEN** ID 1〜5 が 1 行ずつ表示され、続く 1 行に残り 2 件が件数で表示される

#### Scenario: すべて完了
- **GIVEN** パネルが展開されていて、項目が 3 件あり、すべて完了している
- **WHEN** パネルが描画される
- **THEN** 「all done」を含む 1 行だけが表示される

#### Scenario: 項目が無い
- **GIVEN** パネルが展開されている
- **WHEN** 現在のブランチに TODO 項目が無い
- **THEN** パネルは表示されない

#### Scenario: 上限の変更
- **GIVEN** `SPIRITS_TODO_MAX_LINES=3` で起動し、パネルが展開されている
- **WHEN** 未完了が 4 件ある状態でパネルが描画される
- **THEN** 項目行は ID 1〜3 の 3 行になり、続く 1 行に残り 1 件が件数で表示される

#### Scenario: 上限の不正値
- **WHEN** `SPIRITS_TODO_MAX_LINES` が `0`、`abc`、`-1` のいずれかで起動する
- **THEN** N は 5 として扱われる

#### Scenario: 長いテキスト
- **GIVEN** パネルが展開されている
- **WHEN** 項目のテキストが端末幅より長い
- **THEN** その項目は 1 行に切り詰めて表示され、パネルの行数は増えない

#### Scenario: ツール呼び出し後の更新
- **WHEN** `manage_todos` の呼び出しが成功する
- **THEN** 同じ呼び出しの完了時点でパネルが新しい状態を表示する

#### Scenario: `/reload` 後の再表示
- **GIVEN** 未完了の項目があり、パネルが展開されている
- **WHEN** ユーザーが `/reload` を実行する
- **THEN** reload 完了後にパネルが同じ TODO 内容で再表示される(開閉状態は「開閉状態はセッション開始時に既定へ戻る」に従う)

### Requirement: TODO 状態はセッションファイルに保存され再開時に復元される
システムは `manage_todos` の成功ごとに TODO 状態をセッションファイルへ保存し、セッションの再開時に復元しなければならない。読み取れない保存データは無視し、同じブランチ上でそれより前の有効な状態を使わなければならない。(SHALL)

読み取れない保存データには、JSON として解釈できないものや型が合わないものだけでなく、ID の重複や空白だけのテキストなど、`manage_todos` が生成しえない内容を含む。

#### Scenario: 再開後の復元
- **GIVEN** 永続化されたセッションで、未完了 1 件と完了 1 件を保存して終了した
- **WHEN** ユーザーが `/resume` または `--continue` でそのセッションを再開する
- **THEN** パネルは未完了 1 件と完了 1 件の件数行を表示し、次に追加される項目には保存前の採番を引き継いだ ID が割り当てられる

#### Scenario: 壊れた保存データ
- **GIVEN** 有効な TODO 状態の後に、形式が不正な TODO 状態がセッションファイルに記録されている
- **WHEN** セッションを再開する
- **THEN** 不正な記録は無視され、直前の有効な状態が表示される

#### Scenario: 意味的に不正な保存データ
- **GIVEN** 有効な TODO 状態の後に、ID が重複した TODO 状態がセッションファイルに記録されている
- **WHEN** セッションを再開する
- **THEN** 重複を含む記録は無視され、直前の有効な状態が表示される

### Requirement: TODO パネルはキー入力で開閉できる
システムは対話 TUI で、ユーザーが開閉キーを押したときに TODO パネルを展開と折りたたみの間で切り替えなければならない。(SHALL) 現在のブランチに TODO 項目が無いときは、開閉キーを押しても開閉状態を変えてはならない。(MUST) 開閉の切り替えは TODO の保存状態を変更してはならない。(MUST)

#### Scenario: 展開から折りたたみへの切り替え
- **GIVEN** 未完了 3 件と完了 2 件があり、パネルが展開されている
- **WHEN** ユーザーが開閉キーを押す
- **THEN** パネルは `3 pending · 2 done` の 1 行だけを表示し、項目行を表示しない

#### Scenario: 折りたたみから展開への切り替え
- **GIVEN** 未完了 3 件と完了 2 件があり、パネルが折りたたまれている
- **WHEN** ユーザーが開閉キーを押す
- **THEN** 未完了 3 件の項目行と、完了 2 件の件数行を表示する

#### Scenario: 開閉しても保存状態は変わらない
- **GIVEN** 未完了の項目 ID 1 がある
- **WHEN** ユーザーが開閉キーを 2 回押す
- **THEN** パネルの表示は元に戻り、セッションファイルに新しい TODO 状態は記録されない

#### Scenario: 項目が無いときは開閉しない
- **GIVEN** パネルが展開されていて、現在のブランチに TODO 項目が無い
- **WHEN** ユーザーが開閉キーを押し、その後 `manage_todos` で項目を 1 件追加する
- **THEN** パネルは展開状態で、追加された項目の行を表示する

### Requirement: 開閉キーは設定ファイル、環境変数、既定値の順に決まる
システムは開閉キーを、次の候補の順に最初に採用できた値で決めなければならない。(SHALL)
1. グローバル設定ファイル(`<agentDir>/settings.json`)の `todo.toggleKey`
2. 環境変数 `SPIRITS_TODO_TOGGLE_KEY`
3. 既定値 `ctrl+shift+l`

値が無い、文字列でない、または構文として解釈できない候補は未設定として扱い、次の候補へ進まなければならない。(MUST) 設定ファイルが存在しない、JSON として解釈できない、またはオブジェクトでない場合は、設定ファイルに値が無いものとして扱わなければならず、拡張の読み込みを失敗させてはならない。(MUST) 設定は拡張の読み込み時に読み、変更は次の `/reload` または起動から反映する。

#### Scenario: 既定キー
- **GIVEN** 設定ファイルに `todo.toggleKey` が無く、`SPIRITS_TODO_TOGGLE_KEY` も設定されていない
- **WHEN** 未完了の項目がある状態でユーザーが `ctrl+shift+l` を押す
- **THEN** パネルが展開と折りたたみの間で切り替わる

#### Scenario: 設定ファイルでの変更
- **GIVEN** 設定ファイルに `"todo": { "toggleKey": "ctrl+shift+k" }` があり、`SPIRITS_TODO_TOGGLE_KEY` は設定されていない
- **WHEN** 未完了の項目がある状態でユーザーが `ctrl+shift+k` を押し、次に `ctrl+shift+l` を押す
- **THEN** `ctrl+shift+k` でパネルが切り替わり、`ctrl+shift+l` では切り替わらない

#### Scenario: 設定ファイルが環境変数より優先される
- **GIVEN** 設定ファイルに `"todo": { "toggleKey": "ctrl+shift+k" }` があり、`SPIRITS_TODO_TOGGLE_KEY=ctrl+shift+j` で起動した
- **WHEN** 未完了の項目がある状態でユーザーが `ctrl+shift+j` を押し、次に `ctrl+shift+k` を押す
- **THEN** `ctrl+shift+j` では切り替わらず、`ctrl+shift+k` でパネルが切り替わる

#### Scenario: 環境変数での変更
- **GIVEN** 設定ファイルに `todo.toggleKey` が無く、`SPIRITS_TODO_TOGGLE_KEY=ctrl+shift+j` で起動した
- **WHEN** 未完了の項目がある状態でユーザーが `ctrl+shift+j` を押す
- **THEN** パネルが展開と折りたたみの間で切り替わる

#### Scenario: 設定ファイルの値が構文として解釈できない
- **GIVEN** 設定ファイルの `todo.toggleKey` が `""`、`"ctrl+"`、`"ctrl l"`、数値 `1` のいずれかで、`SPIRITS_TODO_TOGGLE_KEY=ctrl+shift+j` で起動した
- **WHEN** 未完了の項目がある状態でユーザーが `ctrl+shift+j` を押す
- **THEN** パネルが展開と折りたたみの間で切り替わる

#### Scenario: すべての候補が構文として解釈できない
- **GIVEN** 設定ファイルに `todo.toggleKey` が無く、`SPIRITS_TODO_TOGGLE_KEY` が空文字列または `ctrl+` で起動した
- **WHEN** 未完了の項目がある状態でユーザーが `ctrl+shift+l` を押す
- **THEN** パネルが展開と折りたたみの間で切り替わる

#### Scenario: 読めない設定ファイル
- **GIVEN** 設定ファイルが JSON として解釈できず、`SPIRITS_TODO_TOGGLE_KEY` は設定されていない
- **WHEN** 対話 TUI を起動し、未完了の項目がある状態でユーザーが `ctrl+shift+l` を押す
- **THEN** 拡張は読み込まれて `manage_todos` を使え、パネルが展開と折りたたみの間で切り替わる

#### Scenario: 設定の変更は `/reload` で反映される
- **GIVEN** 起動後に、設定ファイルの `todo.toggleKey` を `ctrl+shift+k` に書き換えた
- **WHEN** ユーザーが `ctrl+shift+k` を押し、次に `/reload` を実行してから `ctrl+shift+k` を押す
- **THEN** `/reload` 前の `ctrl+shift+k` ではパネルは切り替わらず、`/reload` 後の `ctrl+shift+k` で切り替わる

### Requirement: 開閉キーは構文だけを検証する
構文として解釈できる値とは、前後の空白を除いて小文字にしたとき、修飾キー `ctrl` `shift` `alt` `super` を 0 個以上それぞれ `+` を付けて並べ、その後に基底キーを 1 つ置いたものをいう。基底キーは英数字の並び、または `+` と空白を除く ASCII 記号 1 文字とする。システムは構文として解釈できるが存在しないキー名を、既定値に戻さずそのまま開閉キーとして採用しなければならない。(SHALL) この場合、どのキーを押してもパネルは切り替わらない。

#### Scenario: 記号の基底キー
- **GIVEN** 設定ファイルに `"todo": { "toggleKey": "alt+," }` がある
- **WHEN** 未完了の項目がある状態でユーザーが `alt+,` を押す
- **THEN** パネルが展開と折りたたみの間で切り替わる

#### Scenario: 大文字と前後の空白
- **GIVEN** 設定ファイルに `"todo": { "toggleKey": " Ctrl+Shift+K " }` がある
- **WHEN** 未完了の項目がある状態でユーザーが `ctrl+shift+k` を押す
- **THEN** パネルが展開と折りたたみの間で切り替わる

#### Scenario: 存在しないキー名
- **GIVEN** 設定ファイルに `"todo": { "toggleKey": "ctrl+foo" }` がある
- **WHEN** 未完了の項目がある状態でユーザーが `ctrl+shift+l` を押す
- **THEN** パネルは切り替わらない

### Requirement: 開閉キーと組み込みキーの衝突は Pi の規則に従う
システムは開閉キーが Pi の組み込みキーと衝突する場合、Pi の衝突規則に従わなければならない。(SHALL) Pi が予約するキーと衝突した場合、開閉キーは登録されず、Pi が警告を表示する。予約されていない組み込みキーと衝突した場合、Pi が警告を表示し、開閉キーが組み込みキーより優先される。

#### Scenario: Pi の予約キーとの衝突
- **GIVEN** 設定ファイルに `"todo": { "toggleKey": "ctrl+l" }` がある
- **WHEN** 対話 TUI を起動し、未完了の項目がある状態でユーザーが `ctrl+l` を押す
- **THEN** 起動時に Pi がショートカット衝突の警告を表示し、`ctrl+l` はモデル選択を開き、パネルは切り替わらない

#### Scenario: Pi の予約外の組み込みキーとの衝突
- **GIVEN** 設定ファイルに `"todo": { "toggleKey": "ctrl+]" }` がある
- **WHEN** 対話 TUI を起動し、未完了の項目がある状態でユーザーが `ctrl+]` を押す
- **THEN** 起動時に Pi がショートカット衝突の警告を表示し、パネルが切り替わり、エディタの文字ジャンプは始まらない

### Requirement: 折りたたみ時は件数サマリだけを表示する
システムは折りたたみ時のパネルを、項目行を出さずに未完了件数と完了件数だけの 1 行で表示しなければならない。(SHALL) 未完了件数を P、完了件数を D としたとき、未完了件数は `<P> pending` とし、完了項目があるときだけ続けて `<D> done` を区切り ` · ` で示さなければならない。(SHALL) すべての項目が完了しているときは「all done」を含む 1 行を表示し、項目が 0 件のときはパネルを表示してはならない。(MUST) 折りたたみ時の行も端末幅に収まるように切り詰めなければならない。(SHALL)

#### Scenario: 未完了と完了が混在する
- **GIVEN** 折りたたみ中で、未完了 3 件、完了 2 件
- **WHEN** パネルが描画される
- **THEN** `3 pending · 2 done` の 1 行だけが表示される

#### Scenario: 完了項目が無い
- **GIVEN** 折りたたみ中で、未完了 3 件、完了 0 件
- **WHEN** パネルが描画される
- **THEN** `3 pending` の 1 行だけが表示される

#### Scenario: すべて完了
- **GIVEN** 折りたたみ中で、項目が 3 件ありすべて完了している
- **WHEN** パネルが描画される
- **THEN** 「all done」を含む 1 行だけが表示される

#### Scenario: 項目が無い
- **GIVEN** 折りたたみ中で、現在のブランチに TODO 項目が無い
- **WHEN** パネルが描画される
- **THEN** パネルは表示されない

#### Scenario: 長いサマリ
- **WHEN** 折りたたみ中のサマリが端末幅より長い
- **THEN** サマリは 1 行に切り詰めて表示され、行数は増えない

### Requirement: 開閉状態はセッション開始時に既定へ戻る
システムはパネルの開閉状態を実行時にのみ保持し、セッション開始時に既定状態へ戻さなければならない。(SHALL) 既定状態は展開とし、グローバル設定ファイル(`<agentDir>/settings.json`)の `todo.startCollapsed` が真偽値 `true` のときだけ折りたたみで開始しなければならない。(SHALL) 値が無い、`true` 以外の値(文字列 `"true"` を含む)、または設定ファイルを読めない場合は展開で開始しなければならない。(MUST) セッション開始以外の再描画(ブランチ移動や `manage_todos` の成功)では、開閉状態を変更してはならない。(MUST)

#### Scenario: 既定は展開
- **GIVEN** 設定ファイルに `todo.startCollapsed` が無い状態で起動した
- **WHEN** 未完了 1 件があるセッションを開始する
- **THEN** パネルは項目行を表示する

#### Scenario: 折りたたみで開始する
- **GIVEN** 設定ファイルに `"todo": { "startCollapsed": true }` がある状態で起動した
- **WHEN** 未完了 3 件と完了 2 件があるセッションを開始する
- **THEN** パネルは `3 pending · 2 done` の 1 行だけを表示する

#### Scenario: 開始状態の不正値
- **GIVEN** 設定ファイルの `todo.startCollapsed` が `"true"`、`1`、`false` のいずれかの状態で起動した
- **WHEN** 未完了 1 件があるセッションを開始する
- **THEN** パネルは項目行を表示する

#### Scenario: ツール成功後も開閉状態を保つ
- **GIVEN** 折りたたみ中で、未完了 1 件がある
- **WHEN** `manage_todos` で新しい項目を 1 件追加する
- **THEN** パネルは折りたたみのまま `2 pending` を表示する

#### Scenario: ブランチ移動では開閉状態を変えない
- **GIVEN** ユーザーがパネルを折りたたんでいる
- **WHEN** ユーザーが `/tree` で、TODO 項目がある別のブランチへ移動する
- **THEN** パネルは折りたたみのまま、移動先のブランチの件数サマリを表示する

#### Scenario: セッション開始で既定へ戻る
- **GIVEN** 設定ファイルに `todo.startCollapsed` が無く、ユーザーがパネルを折りたたんでいる
- **WHEN** ユーザーが `/reload` を実行する
- **THEN** パネルは展開状態で再表示される
