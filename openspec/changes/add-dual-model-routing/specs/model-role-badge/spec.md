# Spec Delta

## Purpose

対話 TUI のフッター右側で、直近のリクエストがどのロールで処理されたかを利用者に伝える。モデルを切り替えずにロールだけが変わるため、現在のモデル表示だけでは強いモデルで走っているか判断できない。

## ADDED Requirements

### Requirement: ロールバッジの表記
システムは、セッションにロールが記録されているとき、フッター右側表示の先頭に角括弧で囲んだロール名を小文字で表記しなければならない。(SHALL)
ロールが記録されていないとき、システムはバッジを出さず、従来の右側表示のままでなければならない。(SHALL)
記録されたロールに改行や制御文字が含まれる場合、システムはそれらを取り除いて 1 行で表記しなければならない。(SHALL)

#### Scenario: 制御文字を含むロール
- **GIVEN** 記録されたロールが改行を含む文字列である
- **WHEN** フッターを描画する
- **THEN** バッジは改行を含まず、統計行は 1 行のまま描画される

#### Scenario: strong のときの表記
- **GIVEN** 記録されたロールが strong で、表示されるモデルが `claude-opus-4-7`、thinking レベルが high である
- **WHEN** フッターを描画する
- **THEN** 右側表示は `[strong]` で始まる

#### Scenario: 物理モデルを直接選んでいる間はバッジがない
- **GIVEN** 現在のモデルが物理モデルであり、ロールは記録されていない
- **WHEN** フッターを描画する
- **THEN** バッジを出さず、`(provider)` 前置とモデル名は従来のまま出す

### Requirement: バッジの位置
システムは、バッジを右側表示の他の要素より前に置かなければならない。(SHALL) provider の接頭辞、選択中のモデル名と thinking レベル、および `→ <routed>` 表示は、いずれもバッジの後ろに続く。

#### Scenario: provider 接頭辞より前
- **GIVEN** 利用可能な provider が 2 つ以上あり、記録されたロールが normal である
- **WHEN** フッターを描画する
- **THEN** 右側表示は `[normal] (<provider>) <モデル名> • <レベル>` の順になる

#### Scenario: routed 表示より前
- **GIVEN** 選択中が `spirits/auto` で、直近のリクエストが strong で `claude-opus-4-7` にルートされている
- **WHEN** フッターを描画する
- **THEN** 右側表示は `[strong] (spirits) auto • <レベル> → claude-opus-4-7 • <レベル>` の順になる

### Requirement: 幅不足時の優先順位
システムは、右側表示が収まらないとき、provider の接頭辞、末尾、右側表示全体の順に縮退しなければならない。(SHALL) バッジはモデル名と `→ routed` 表示より後に失われる。

#### Scenario: provider 接頭辞から落とす
- **GIVEN** バッジとモデル名が収まり、provider 接頭辞を足すと収まらない幅
- **WHEN** フッターを描画する
- **THEN** provider の接頭辞を出さず、`[<ロール>] <モデル名> …` はそのまま出す

#### Scenario: 末尾から切り詰める
- **GIVEN** バッジとモデル名を足すとやや収まらない幅
- **WHEN** フッターを描画する
- **THEN** 末尾（`→ routed` 表示と thinking レベル）から切り詰め、バッジは先頭に残る

#### Scenario: バッジ分も確保できない幅
- **GIVEN** ロールが記録されており、右側表示を置く余地がない幅
- **WHEN** フッターを描画する
- **THEN** バッジを含む右側表示全体を出さず、統計側だけを出す

### Requirement: バッジの更新タイミング
システムは、記録されたロールを表示し、新しいリクエストが振り分けられるまでバッジを更新してはならない。(MUST)
スキルの起動だけではバッジは変わらない。スキル実行の終了後も、次のリクエストが振り分けられるまでバッジは強いロールのまま残る。スキルの実行は 1 つの run に対応すると前提し、複数の run に跨るスキルのバッジ遷移は未定義とする。

#### Scenario: スキル起動直後は変わらない
- **GIVEN** 記録されたロールが normal で、deep verify スキルを起動した直後であり、まだリクエストが出ていない
- **WHEN** フッターを描画する
- **THEN** バッジは `[normal]` である

#### Scenario: スキル実行中のリクエストで切り替わる
- **GIVEN** deep verify スキルの実行中である
- **WHEN** その run の最初のリクエストが振り分けられ、応答が返る
- **THEN** バッジは `[strong]` になる

#### Scenario: スキル終了直後は強いロールのまま
- **GIVEN** deep verify スキルの run が strong で完了し、settled した直後である
- **WHEN** 次の入力をする前にフッターを描画する
- **THEN** バッジは `[strong]` のままであり、次のリクエストの振り分け後に `[normal]` へ戻る

#### Scenario: 振り分けが失敗しても変わらない
- **GIVEN** 記録されたロールが normal である
- **WHEN** リクエストの振り分けが失敗する
- **THEN** バッジは `[normal]` のまま表示される
