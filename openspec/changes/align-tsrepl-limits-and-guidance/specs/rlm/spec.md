# Spec Delta

## MODIFIED Requirements

### Requirement: rlm の制約の案内
システムは、`rlm` を登録した tsrepl のツール説明に、`rlm` の制約を含めなければならない。(SHALL) 含める内容は次のとおり。
- 呼び出しが直列に実行され、待ち時間が合計されること
- 1 回の呼び出しの実行時間に上限があることと、その値、上限を超えると例外になること。セル全体の timeout を指定した場合はそれも子の実行時間に適用されること
- 深度上限の値と、そのセッションの深度
- 子のツール呼び出し回数の上限

#### Scenario: ルートセッションの制約の案内
- **WHEN** `rlm` を登録したルートセッション(深度 0、上限 2)の tsrepl のツール説明を取得する
- **THEN** 説明に `timeout`、直列に実行される旨、深度上限 `2`、ツール呼び出し回数の上限 `50`、実行時間の上限 `120000` が含まれる

### Requirement: 深度と登録状況に応じた案内
システムは、`rlm` を呼べない深度のセッション(深度が上限以上)のツール説明には、`rlm` の使い方を含めず、深度上限により `rlm` を呼べない旨だけを含めなければならない。(SHALL)
システムは、`rlm` で起動された子(深度 1 以上)のツール説明に、親エージェントが `rlm` で起動した子であること、最終アシスタントメッセージのテキストが親へ文字列として返ることを含めなければならない。(SHALL)
`rlm` を登録していない tsrepl のツール説明には、`rlm` 固有の案内を含めてはならない。(MUST)

#### Scenario: 深度上限に達したセッションの案内
- **WHEN** 深度 2(上限 2)のセッションの tsrepl のツール説明を取得する
- **THEN** 説明に深度上限により `rlm` を呼べない旨が含まれ、`await rlm(` の使用例は含まれない

#### Scenario: 子向けの案内
- **WHEN** 深度 1 の子セッションの tsrepl のツール説明を取得する
- **THEN** 説明に、親が `rlm` で起動した子である旨と、最終アシスタントメッセージが親へ文字列で返る旨が含まれる

#### Scenario: rlm を登録しない tsrepl の説明
- **WHEN** `rlm` を登録せずに作成した tsrepl のツール説明を取得する
- **THEN** 説明に `await rlm(`、深度上限の値、子のツール呼び出し回数の上限が含まれない

## ADDED Requirements

### Requirement: rlm 呼び出しの実行時間上限
システムは、1 回の `rlm` 呼び出しについて、子セッションの実行時間に上限(既定 120000ms)を設け、上限を超えた時点で子セッションを中断し、その完了を待ってから戻らなければならない。直列化の待機時間は上限に含めない。(SHALL)
上限で中断したとき、`rlm` は、実行時間の上限で打ち切った旨と上限の値を含む例外を投げなければならない。この例外はセル内で catch できなければならない。(SHALL)
上限のタイマーが発火した後でも、子セッションが完了(`outcome` が `completed`)して戻った場合は、上限を理由とする例外を投げずに子の最終回答を返し、`outcome` は `completed` として記録しなければならない。(SHALL)
上限での中断は `rlm_usage` に `outcome` `aborted` として記録し、`durationMs` には戻りまでの経過時間、tokens と cost には中断時点までの値を記録しなければならない。(SHALL)

#### Scenario: 上限超過での中断
- **WHEN** 子が実行時間の上限を超えて走り続けている状態で `await rlm("x")` を実行する
- **THEN** 子セッションは中断され、セルの error が返り、実行時間の上限で打ち切った旨とその上限値が含まれる

#### Scenario: 上限での中断の catch
- **WHEN** 子が実行時間の上限を超えて走り続けている状態で、セル `try { await rlm("x") } catch (e) { return String(e) }` を実行する
- **THEN** セルの error は返らず、value に実行時間の上限で打ち切った旨とその上限値が含まれる

#### Scenario: 上限の発火と同時の完了
- **WHEN** 実行時間の上限のタイマーが発火した後で、子が最終回答 `"done"` で完了して戻る
- **THEN** `rlm` は `"done"` を返し、上限を理由とする例外は投げられず、`rlm_usage` の `outcome` は `completed` になる

#### Scenario: 上限内での完了
- **WHEN** 子が実行時間の上限内に最終回答 `"done"` で完了する
- **THEN** 子は中断されず、`rlm` は `"done"` を返す

#### Scenario: 直列化の待機は上限に含めない
- **WHEN** 1 つ目の `rlm` が上限の半分の時間かかって完了した後、2 つ目の `rlm` が上限内に完了する
- **THEN** 2 つ目は中断されず、子の最終回答が返る

#### Scenario: 上限での中断の記録
- **WHEN** 子が実行時間の上限で中断されるまでに input 50 のトークンを使った
- **THEN** `outcome` が `aborted`、tokens の input が 50、`durationMs` が上限以上の `rlm_usage` エントリが追加される

#### Scenario: 親の中断との区別
- **WHEN** 実行時間の上限に達する前に、親セルの中断シグナルが abort される
- **THEN** セルの error には呼び出し元の中断で打ち切った旨が含まれ、実行時間の上限で打ち切った旨は含まれない
