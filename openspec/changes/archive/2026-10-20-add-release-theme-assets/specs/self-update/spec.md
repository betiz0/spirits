# Spec Delta

## MODIFIED Requirements

### Requirement: 自己更新のリリース解決と検証
自己更新は、`VERSION` を指定しないインストーラと同じ規則で最新版を解決しなければならない。すなわち、Releases API が返す作成日時の新しい順の一覧(1 ページ 100 件)から、draft と prerelease を除いた `spirits-v*` タグのリリースの先頭を最新として使わなければならない。(SHALL)
自己更新は、実行ファイルを置換する場合、解決したリリースの `spirits-linux-x64`、`spirits-linux-x64.sha256`、`dark.json`、`light.json`、およびテーマ資産の `.sha256` を取得し、配置前にチェックサムを検証しなければならない。(SHALL)
自己更新は、テーマ資産を修復する場合、解決したリリースの `dark.json`、`light.json`、およびその `.sha256` を取得し、配置前にチェックサムを検証しなければならない。(SHALL)
チェックサム検証に失敗した場合、インストール済みの実行ファイルと既存のテーマ資産を変更せず、非ゼロで終了しなければならない。(MUST)

#### Scenario: prerelease と pi リリースの除外
- **WHEN** `spirits-v0.3.0` より新しい prerelease の `spirits-v0.4.0-rc.1` と、pi のリリース `v1.0.0` がある環境で `spirits update` を実行する
- **THEN** `spirits-v0.3.0` の成果物が更新対象になる

#### Scenario: チェックサム不一致
- **WHEN** ダウンロードされる実行ファイルが `.sha256` と一致しない状態で `spirits update` を実行する
- **THEN** 終了コードは非ゼロになり、インストール済みの実行ファイルは元の内容のまま残る

#### Scenario: テーマ資産のチェックサム不一致
- **WHEN** ダウンロードされるテーマ資産が `.sha256` と一致しない状態で `spirits update` を実行する
- **THEN** 終了コードは非ゼロになり、インストール済みの実行ファイルと既存のテーマ資産は元の内容のまま残る

#### Scenario: stable リリース未検出
- **WHEN** 通常の(draft でも prerelease でもない)`spirits-v*` リリースが存在しない状態で `spirits update` を実行する
- **THEN** 解決に失敗した旨が表示され、終了コードは非ゼロになり、実行ファイルは変更されない

### Requirement: 自己更新の原子性
自己更新は、置換のどの時点でも、インストール先のパスが元の実行ファイル全体か、検証済みの新しい実行ファイル全体のいずれかになるように置換しなければならない。(SHALL)
テーマ資産を配置する場合、各ファイルは元の内容全体か、検証済みの新しい内容全体のいずれかでなければならない。(SHALL)
置換が完了するまで、インストール済みの実行ファイルは元の内容と実行ビットを保たなければならない。(SHALL)
置換後の実行ファイルは実行ビットを持たなければならない。(SHALL)
複数の自己更新、または自己更新とインストーラが同時に実行された場合も、インストール先はいずれかの実行が配置した検証済みの実行ファイル全体で、各テーマ資産はいずれかの実行が配置した完全なファイルでなければならない。(SHALL)

#### Scenario: 成功時の置換
- **WHEN** チェックサム検証済みの自己更新が完了する
- **THEN** インストール先の実行ファイルは新しい内容で実行ビットを持ち、テーマ資産は新しい完全な内容になり、次回起動から新しいバージョンが使われる

#### Scenario: 置換失敗時の元ファイル維持
- **WHEN** インストール先ディレクトリへの書き込みが置換の完了前に失敗する
- **THEN** 終了コードは非ゼロになり、インストール済みの実行ファイルは元の内容と実行ビットを保ち、テーマ資産は元の内容か新しい完全な内容のいずれかになる

#### Scenario: 同時実行
- **WHEN** 同じインストール先に対して 2 つの `spirits update --force` を同時に実行する
- **THEN** 両方の終了後、インストール先は検証済みの実行ファイル全体で実行ビットを持ち、各テーマ資産は完全なファイルである

## ADDED Requirements

### Requirement: 自己更新のテーマ資産
自己更新は、実行ファイルを置換するとき、解決したリリースの `dark.json` と `light.json` を実行ファイルと同じディレクトリの `theme/` に配置しなければならない。(SHALL)
インストール済みバージョンが最新版と等しく、テーマ資産が欠けている場合、自己更新は実行ファイルを置換せずにテーマ資産を配置しなければならない。(SHALL)
インストール済みバージョンが解決された最新版より新しい場合、自己更新はテーマ資産を取得・配置してはならない。(SHALL)
テーマ資産の取得または配置に失敗した場合、自己更新は非ゼロで終了し、実行ファイルは置換前の内容を保たなければならない。各テーマ資産は、配置が完了したものが検証済みの新しい内容、それ以外が元の内容でなければならない。(SHALL)

#### Scenario: 更新時のテーマ配置
- **WHEN** 0.2.0 がインストール済みで最新 stable が 0.3.0 のとき `spirits update` を実行する
- **THEN** 実行ファイルは 0.3.0 に置き換わり、`theme/dark.json` と `theme/light.json` は 0.3.0 の内容で配置される

#### Scenario: 最新時のテーマ修復
- **WHEN** 0.3.0 がインストール済みでテーマ資産が欠けているとき `spirits update` を実行する
- **THEN** 実行ファイルは置換されず、テーマ資産だけが配置され、終了コードは 0 になる

#### Scenario: 旧版の updater が残したテーマ欠落の修復
- **WHEN** 旧版の updater が 0.3.0 の実行ファイルだけを配置し、テーマ資産が欠けている状態で新しい 0.3.0 の `spirits update` を実行する
- **THEN** 実行ファイルは置換されず、`theme/dark.json` と `theme/light.json` が配置される

#### Scenario: テーマ資産を持たないリリースでの更新失敗
- **WHEN** 解決した最新版のリリースがテーマ資産を持たない状態で `spirits update` を実行する
- **THEN** 終了コードは非ゼロになり、実行ファイルと既存のテーマ資産は元の内容のまま残る

#### Scenario: 最新より新しい場合の非修復
- **WHEN** 0.4.0-rc.1 がインストール済みで最新 stable が 0.3.0、テーマ資産が欠けているとき `spirits update` を実行する
- **THEN** 実行ファイルは変更されず、テーマ資産は取得も配置も行われず、stable の最新版より新しい旨が表示され、終了コードは 0 になる
